# Управление SSL сертификатами

## Обзор

Проект использует Let's Encrypt для автоматического получения и обновления SSL сертификатов через Certbot.

## Скрипты

### 1. `safe-deploy.sh` - Основной скрипт деплоя

Автоматически проверяет и управляет SSL сертификатами при деплое:

```bash
./safe-deploy.sh
```

**Что делает:**
- ✅ Проверяет наличие SSL сертификатов
- ✅ Проверяет срок действия (если осталось < 30 дней - автоматически обновляет)
- ✅ Запускает Certbot в фоновом режиме для автообновления каждые 12 часов
- ✅ Проверяет конфигурацию Nginx
- ✅ Показывает статус сертификата после деплоя

### 2. `init-letsencrypt.sh` - Первоначальное получение сертификата

Используется для первого получения SSL сертификата:

```bash
./init-letsencrypt.sh
```

**Когда использовать:**
- При первом запуске на новом сервере
- Если сертификаты были удалены
- Для добавления новых доменов

**Процесс:**
1. Переключается на HTTP-only конфигурацию
2. Запрашивает сертификат через webroot метод
3. Восстанавливает HTTPS конфигурацию
4. Перезапускает Nginx с SSL

### 3. `renew-cert.sh` - Ручное обновление сертификата

Для принудительного обновления сертификата:

```bash
./renew-cert.sh
```

**Когда использовать:**
- Для проверки процесса обновления
- При проблемах с автоматическим обновлением
- Для принудительного обновления (если осталось < 30 дней)

### 4. `init-letsencrypt-standalone.sh` - Альтернативный метод

Получение сертификата в standalone режиме (останавливает Nginx):

```bash
./init-letsencrypt-standalone.sh
```

**Когда использовать:**
- Если webroot метод не работает
- При проблемах с конфигурацией Nginx

## Автоматическое обновление

Certbot контейнер работает в фоновом режиме и автоматически:
- Проверяет сертификаты каждые 12 часов
- Обновляет сертификаты за 30 дней до истечения
- Перезагружает Nginx после обновления

## Проверка статуса сертификата

### Проверка срока действия:

```bash
openssl x509 -enddate -noout -in ./certbot/conf/live/sushiritto.ru/cert.pem
```

### Просмотр логов Certbot:

```bash
docker compose logs certbot
docker compose logs -f certbot  # в реальном времени
```

### Проверка конфигурации Nginx:

```bash
docker compose exec nginx nginx -t
```

## Структура файлов

```
certbot/
├── conf/                           # Конфигурация и сертификаты
│   ├── live/sushiritto.ru/        # Активные сертификаты
│   │   ├── cert.pem               # Сертификат
│   │   ├── chain.pem              # Цепочка сертификатов
│   │   ├── fullchain.pem          # Полная цепочка
│   │   └── privkey.pem            # Приватный ключ
│   ├── archive/                   # Архив старых сертификатов
│   ├── renewal/                   # Конфигурация обновления
│   ├── options-ssl-nginx.conf     # Рекомендуемые SSL параметры
│   └── ssl-dhparams.pem           # DH параметры
└── www/                           # Webroot для ACME challenge
```

## Troubleshooting

### Сертификат не обновляется автоматически

1. Проверьте логи Certbot:
   ```bash
   docker compose logs certbot
   ```

2. Проверьте что контейнер запущен:
   ```bash
   docker compose ps certbot
   ```

3. Попробуйте ручное обновление:
   ```bash
   ./renew-cert.sh
   ```

### Ошибка "Failed to renew certificate"

**Возможные причины:**
- DNS не указывает на сервер
- Порт 80 недоступен из интернета
- Проблемы с конфигурацией Nginx

**Решение:**
1. Проверьте DNS:
   ```bash
   nslookup sushiritto.ru
   ```

2. Проверьте доступность порта 80:
   ```bash
   curl -I http://sushiritto.ru/.well-known/acme-challenge/test
   ```

3. Проверьте конфигурацию Nginx:
   ```bash
   docker compose exec nginx nginx -t
   ```

### Сертификат истек

Если сертификат уже истек:

1. Остановите Nginx:
   ```bash
   docker compose stop nginx
   ```

2. Используйте standalone метод:
   ```bash
   ./init-letsencrypt-standalone.sh
   ```

3. Запустите Nginx:
   ```bash
   docker compose up -d nginx
   ```

## Тестирование (Staging)

Для тестирования без лимитов Let's Encrypt:

1. Откройте `init-letsencrypt.sh`
2. Измените `staging=0` на `staging=1`
3. Запустите скрипт
4. После проверки верните `staging=0` и запустите снова

## Мониторинг

### Проверка срока действия в safe-deploy.sh

Скрипт автоматически показывает:
- ✅ Сертификат найден
- 📅 Осталось X дней
- ⚠️ Требуется обновление (< 30 дней)

### Настройка алертов

Можно настроить мониторинг через `monitor-service` для отправки уведомлений в Telegram при истечении сертификата.

## Рекомендации

1. **Регулярно проверяйте логи Certbot** после деплоя
2. **Не удаляйте папку certbot/conf** - там хранятся сертификаты
3. **Делайте бэкап сертификатов** перед критическими изменениями
4. **Используйте staging режим** для тестирования изменений
5. **Проверяйте срок действия** после каждого деплоя
